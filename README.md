# RSNA 2026 Knee Abnormality Detection — super-ensemble solution (public LB 0.958)

My solution to the Kaggle code competition
[RSNA Knee Abnormality Detection](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection): predict 12
findings (ACL, MCL, both menisci, three OA compartments, effusion, synovitis, Baker's cyst, contusion, fracture) from
knee MRI studies, scored by macro ROC AUC. Inference runs in a Kaggle notebook: ≤ 9 h on 2 × T4, internet off, on a
hidden test set of ~1,300 studies. Only 58 training studies carry radiologist labels; the other ~4,350 have free-text
reports from which labels have to be derived.

**Result: public leaderboard 0.958** (submission 57435077; rank 570 of 6,302 teams on 2026-10-21, top 10 %), up from
0.887 for my own DINOv2 pipeline. The private leaderboard is published after the deadline.

## Approach in one picture

```
hidden test ──► Raptor CoAtNet-384, anatomical mirror TTA (nartaa)  ──┐ 0.65
            ├─► Raptor CoAtNet-224, 0.8 crop, mirror TTA (nartaa)   ──┘ 0.35 ─► CoAtNet slot ──┐  CoAtNet share per finding:
            ├─► R6 ConvNeXt-small x4 folds + stackers, flip TTA (heliosli) ┐ 0.60             ├─ 0.5; Synovitis 0.85, PF OA 0.65,
            └─► S6F ConvNeXt-small, all data, JEV labels (nartaa)       ──┘ 0.40 ─► ConvNeXt ─┘   Baker's 0.30, Lateral OA 0.15
                                                                                                  -> per-finding percentile-rank blend
```

The members are public checkpoints, each run with its authors' own scored inference code. What I built is the system
around them and the evidence for every choice:

- **A fault-tolerant multi-model harness** (`super_ensemble/`). Each member runs as its own process group with its
  own deadline inside the 9-hour limit; a member that crashes, hangs or runs late drops out and the blend
  renormalises per study. Every vendored third-party file is pinned by sha256, and each change to it is a named patch
  that must match exactly once. Each run writes receipts (stage status, coverage, rank correlations). The notebook is
  generated by `build_notebook.py` from small stage files.
- **A per-finding percentile-rank blend** with slots, per-finding slot weights and an optional third slot, matching
  the metric (AUC reads only order; members are calibrated very differently).
- **Evaluation on the 58 labelled studies through the unchanged test-time code** (a fake test split of symlinks
  into the training data), with paired bootstrap intervals. This picked the members (S6F added, R7 / S6 / R7-flip
  rejected) and showed where 58 studies stop being informative.
- **A teacher-student pipeline**: leak-free out-of-fold R7 predictions for all 4,349 non-gold training studies,
  reproducing heliosli's hash folds (`int(sha1(uid)[:8], 16) % 4`) and scoring each study only with the fold model
  that never trained on it. I then retrained goodpjw2008's public 2.5D ConvNeXt-T MIL reader on 0.5 × LLM-consensus
  labels + 0.5 × teacher, two seeds on Kaggle T4s (fp16 + GradScaler, EMA).
- **Testing without a GPU**: a local smoke test runs every notebook cell against a fake `/kaggle` tree with stub
  models (blend arithmetic re-derived independently, fallbacks, submission contract). A CPU dry run pushes synthetic
  DICOMs through the student's labels, cache, two-seed training and inference.
- **Kaggle CLI automation** (`kaggle_flow.py`): push (accelerator pinned, quota-aware run caps), wait, fetch logs and
  outputs, submit, wait for scores.

## Results (public leaderboard)

| submission | what changed | public LB |
|---|---|---|
| own DINOv2 line, runs 1-4 | hierarchical MIL on DINOv2-S, LLM report labels | 0.835 → 0.877 → 0.883 → **0.887** |
| super-ensemble v1 / v2 | CoAtNet pair + R7 + S6F (slots 0.5 / 0.4) | 0.957 / 0.957 |
| frontier replica | CoAtNet pair + R6 flip TTA, heliosli's per-finding weights | 0.957 |
| **v3** | the replica + **S6F** in the ConvNeXt slot | **0.958** |
| v3 + goodpjw2008 reader | third slot at 0.3-3.5 % per finding | 0.958 (not above v3 unrounded) |
| v4b | v3 + my student at 0.15 of the ConvNeXt slot + reader | 0.957 |
| non-OAI hedges | ConvNeXt members only (no OAI-trained weights) | 0.955 |

What the measurements say (details in `_analysis/SUPER_ENSEMBLE_RUNS.md` and `_analysis/PATH_TO_0960_REVIEW.md`):

- S6F, trained on a different label set, was the one addition that moved the public score (+0.001 next to R6).
- R6 and R7 are near-duplicates (rank correlation 0.979 on the labelled studies), so running both buys nothing.
- My student reached a clean 0.916 macro AUC on the 58 labelled studies (goodpjw2008's original: 0.911). That is
  below the members (~0.93), and it correlates 0.87-0.90 with them, so it diluted the blend (−0.001). An addition
  must be both stronger and less correlated.
- 58 labelled studies (9-35 positives per finding) cannot separate blends that differ by 0.001. Weights tuned on
  them per finding lose on the public board, as goodpjw2008 measured publicly.

## Reproduce

```bash
python3 super_ensemble/build_notebook.py                 # writes the notebook and super_ensemble/kernel/*/
python3 super_ensemble/tests/local_smoke.py --scratch /tmp/knee_smoke
python3 super_ensemble/tests/teacher_smoke.py --scratch /tmp/knee_teacher
```

Pushing and submitting needs a Kaggle account with the competition joined, the Kaggle CLI 2.x
(`pip install "kaggle==2.2.4"`) and the public datasets listed in `ATTACHING_INPUTS.md`. Then run
`python3 super_ensemble/kaggle_flow.py push submit`, then `wait submit`, then `submit --version <N> -m "..."`; see
`KAGGLE_RUNBOOK.md`. The student's CPU dry run needs torch, timm, pydicom and opencv:
`python super_ensemble/tests/student_smoke.py --scratch <dir> --reader <dir with goodpjw2008's knee.py and preprocess.py>`.

No competition data is included (the competition rules forbid redistributing it). Kaggle run outputs, which hold
labelled-study predictions, are not part of this repository.
