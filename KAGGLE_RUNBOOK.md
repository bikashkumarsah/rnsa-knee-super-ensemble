# Kaggle runbook: the super-ensemble (Kaggle CLI only)

`BEST_NOTEBOOK_RSNA_KNEE.ipynb` is generated by `super_ensemble/build_notebook.py`. It is an inference-only rank blend
of four public checkpoints run with their authors' own scored code (see `_analysis/OCT15_PUBLIC_NOTEBOOKS_AUDIT.md`):

| slot (v3 weight) | member | inner weight | public LB alone | gold-58 alone |
|---|---|---|---|---|
| CoAtNet (per finding: 0.5; Synovitis 0.85, PF OA 0.65, Baker's 0.30, Lateral OA 0.15) | nartaa Raptor-384, anatomical mirror TTA | 0.65 | 0.949 | 0.923 (optimistic) |
| CoAtNet (same) | nartaa Raptor-224 (0.8 crop), mirror TTA | 0.35 | 0.945 | 0.916 (optimistic) |
| ConvNeXt (1 − CoAtNet) | heliosli R6 (bundle `fe055406fad6a12f`), 4 folds + stackers, flip TTA | 0.60 | — (0.957-0.958 with the CoAtNet pair) | pending |
| ConvNeXt (1 − CoAtNet) | nartaa S6F, S6 architecture on all data, JEV labels, no OAI | 0.40 | 0.950 | 0.931 |

The weights live in `CONFIG` in `super_ensemble/build_notebook.py` (v1: slots 0.5/0.5 with R7 + S6F, submission
57219200; v2: 0.4/0.6, submission 57221549; v3: the table above, heliosli's per-finding weights from his 0.9586 public
blend, kernel version 3).  R7, heliosli's S6, R7/R6 flip variants and the student model (stage 4a) are optional
members switched by `KNEE_R7`, `KNEE_S6`, `KNEE_R7F`, `KNEE_R6`, `KNEE_R6F`, `KNEE_STU`. With only R7 in the ConvNeXt slot and 50/50 slots the blend is exactly
heliosli's public 0.957 recipe. heliosli's S6 and R7 with flip TTA are wired in as optional members (`KNEE_S6`,
`KNEE_R7F`) and were evaluated on gold-58; neither helped, so both are off. Our previous pipeline (DINOv2, 0.887) is archived
as `10_experiments/BEST_NOTEBOOK_RSNA_KNEE_0887_2026-08-24.ipynb`.

All Kaggle actions go through the CLI 2.x in `.venv-kaggle` (`super_ensemble/kaggle_flow.py` wraps it). The base
anaconda CLI (1.7) cannot pin the accelerator; an unpinned push may land on one P100 and halve the ConvNeXt stages.

## 0. One-time setup

```bash
python3 -m venv .venv-kaggle && .venv-kaggle/bin/pip install "kaggle==2.2.4"
```

Credentials are the usual `~/.kaggle/kaggle.json`. Check quota and today's submissions with
`.venv-kaggle/bin/kaggle quota` and `.venv-kaggle/bin/kaggle competitions submission-limits rsna-knee-abnormality-detection`.

## 1. Build and test locally

```bash
python3 super_ensemble/build_notebook.py
```

```bash
python3 super_ensemble/tests/local_smoke.py --scratch /tmp/knee_smoke
```

The builder refuses a vendored file whose sha256 changed and a patch whose anchor does not match exactly once. The smoke
test runs every notebook cell against a fake `/kaggle` tree with stub model processes and checks the blend arithmetic,
the fallbacks and the submission contract; with `--input <dir>` holding `datasets/<owner>/<slug>` copies of nartaa's
S6F dataset and heliosli's OrthoFoundation dataset it also runs the real S6F code-tree preparation.

## 2. Inputs (declared in `super_ensemble/kernel/*/kernel-metadata.json`)

- competition `rsna-knee-abnormality-detection`
- `nartaa/rsna-knee-publication-swa-weights-20261007` (Raptor-384 + Raptor-224)
- `heliosli/rsna-knee-r6-frozen-fe055406` (R7 bundle `8c7b666e27dc0e8f`, heliosli's frozen copy)
- `heliosli/rsna-orthofoundation-fold0-epoch7-20261004` (decode code, SKM-TEA anatomy V-Net, pinned wheels)
- `nartaa/rsna-knee-s6fall-weights` (S6F checkpoint + its code payload)

Internet off, GPU T4 x2. Every checkpoint and code file is sha-checked inside the notebook.

## 3. Evaluate on the 58 labelled studies (optional, ~1 h of GPU quota)

```bash
python3 super_ensemble/kaggle_flow.py push gold58
```

```bash
python3 super_ensemble/kaggle_flow.py wait gold58
```

```bash
python3 super_ensemble/kaggle_flow.py fetch gold58
```

`super_ensemble/runs/gold58/gold58_auc.csv` holds per-member and per-variant AUCs. R7 and S6F never trained on these 58;
nartaa selected the Raptor checkpoints on them, so Raptor's numbers are optimistic. 58 studies give an SE near 0.02: a
sanity check, not a tuning target. The run's stage timings are the best per-study cost estimate for the hidden test.

## 4. Commit the submission kernel

```bash
python3 super_ensemble/kaggle_flow.py push submit
```

```bash
python3 super_ensemble/kaggle_flow.py wait submit
```

```bash
python3 super_ensemble/kaggle_flow.py fetch submit
```

The commit run scores the 3 visible test studies in about 15 minutes. Check `runs/submit/blend_receipt.json`: all four
members used, coverage 1.0, and `stage_status.json` shows every stage `ok`.

## 5. Submit (counts against the 5 per day)

Four kernels share the notebook: `submit` (the four-model blend, `BEST_NOTEBOOK_RSNA_KNEE.ipynb`), `gold58`
(evaluation on the labelled studies, never submitted), `convnext` (the non-OAI hedge: R7 + S6F only, the Raptor
weights neither attached nor run) and `probe` (slot-weight probes, e.g. CoAtNet 0.3). Each has its own `CONFIG` entry in
`super_ensemble/build_notebook.py`, so the main kernel's version history only holds candidate finals.

```bash
python3 super_ensemble/kaggle_flow.py submit --version <N> -m "super-ensemble vN"
```

```bash
python3 super_ensemble/kaggle_flow.py submit --kernel convnext --version <N> -m "non-OAI hedge vN"
```

```bash
python3 super_ensemble/kaggle_flow.py wait-score <submission ref>
```

```bash
python3 super_ensemble/kaggle_flow.py scores
```

The hidden-test rerun takes several hours. Record the version, message and public score in
`10_experiments/EXPERIMENT_LOG.md`.

## 5b. Teacher and student kernels (not submissions)

| kernel | what | inputs | cost |
|---|---|---|---|
| `teacher` / `teacherb` | out-of-fold R7 on the non-gold training studies, folds 0-1 / 2-3 (heliosli's hash folds `int(sha1(uid)[:8], 16) % 4`: each study scored only by the fold model that never trained on it) -> `teacher_r7oof.csv` | R7 bundle, code dataset | ~1.8 h each, in parallel |
| `studentsmoke` | 160 studies, 1 epoch, LLM labels only: checks the real DICOMs and times the steps | goodpjw2008's reader dataset, four public LLM label datasets | ~0.5 h |

Smoke run 2026-10-20: the four label sets load (consensus gold-58 AUC 0.896, best single set 0.893); 1,053 series of 218 studies cached in 2.7 min with 4 processes and no decode error (only the pure-Python pylibjpeg wheel matches Kaggle's current Python, and none of the others was needed); ConvNeXt-T at 256 px, 2 studies x 8 windows per slot: peak 8.1 GB, ~0.9-1.2 s per step after warm-up. The full run therefore uses 8 epochs with 6 training windows per slot (~3.6 h of training + ~1.1 h of caching).
| `student` | `super_ensemble/student/train_student.py`: goodpjw2008's 2.5D ConvNeXt-T MIL reader retrained on 0.5 LLM consensus + 0.5 R7 OOF, two seeds, gold-58 after every epoch -> `student_s0.pt`, `student_s1.pt` | as above + both teacher kernels' outputs | ~5 h |

Local checks: `python3 super_ensemble/tests/teacher_smoke.py --scratch <dir>` (system Python) and, in a venv with torch +
timm + pydicom, `python super_ensemble/tests/student_smoke.py --scratch <dir> --reader <dir with knee.py, preprocess.py>`
(synthetic DICOMs through labels, cache, two-seed training and the inference script).

## 6. Time plan inside the notebook (Kaggle stops a GPU notebook at 9 h)

| stage | starts | deadline / kill (4 members) | with an optional 5th member | measured cost |
|---|---|---|---|---|
| Raptor-384 | 0 | kill 2.0 h | same | ~1.5 s/study (~30 min) |
| Raptor-224 | only before 3.0 h | +1.5 h | same | ~0.8 s/study (~17 min) |
| R7 | only before deadline − 0.5 h | 5.6 h / 5.95 h | 4.3 h / 4.65 h | ~12 s GPU/study/T4 + 5 min compile (~2.3 h) |
| S6F | only before 7.6 h (5.8 h) | 8.35 h / 8.55 h | 6.2 h / 6.45 h | ~8 s/study/T4 (~1.4 h) |
| student (stage 4a, optional) | after S6F, only before 5.6 h | 6.3 h / 6.5 h | same | decode ~0.5 s/study with 4 loaders (~11 min) |
| S6, R7-flip, R6 or R6-flip (optional) | after S6F | — | 8.35 h / 8.55 h | ~2.3 h (R6 flip ~4.2 h) |
| blend | last | — | — | seconds |

Costs are from the gold58 run (58 studies, T4 x2); the 3-study commit logs overstate decode because each loader
worker's one-off setup lands on its first study.

A stage past its deadline keeps the studies it scored; studies it never reached keep the other members. Every fallback
is printed (`BLEND_FALLBACK`) and recorded in `blend_receipt.json`.
